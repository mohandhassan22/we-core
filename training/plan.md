# خطة تنفيذ we core trainer — Static

## النطاق
- صفحة عربية RTL باسم **we core trainer** داخل مشروع WE-Core.
- الواجهة المنشورة Static بالكامل: HTML وCSS وJavaScript فقط داخل مجلد `public/`، بدون Node server أو API خاص بالمشروع.
- خمس وحدات تدريبية بملخصات مبسطة مستندة إلى صفحات الباقات ومحتوى `we-core` الحالي وبيانات Supabase.
- فيديوهات مدمجة من Google Drive وYouTube.
- اختبار تحديد مستوى أولي، واختبارات اختيار من متعدد لكل وحدة مع تفسير الإجابة.
- حفظ الإكمال والدرجات والمحاولات لكل موظف من الواجهة مباشرة في Supabase.
- الموظف يرى تقدمه ونتائجه، ومدير الفرع يرى تقدم موظفي فرعه فقط.
- استخدام دالة Supabase `trainer-ai` عند طلب شرح أو أسئلة جديدة، بدون كشف أي مفتاح AI في المتصفح.

## قرار البنية
- لا يوجد `server.js` أو `package.json` أو Backend خاص بالمشروع.
- Webdev ينشر مجلد `public/` بعقد Static build: الأمر `true`، والنتيجة لا تحتاج تثبيت dependencies.
- Supabase هو الخدمة الخارجية الوحيدة للهوية والبيانات والصلاحيات؛ لذلك يظل تسجيل الدخول عبر جلسة Supabase الموجودة في WE-Core، ولا يتم استخدام Local Storage للمصادقة.
- عند فتح المعاينة بدون جلسة، يستخدم `?demo=1` للعرض التجريبي فقط؛ هذا الوضع لا يحفظ بيانات حقيقية ولا يتاح في مسار الموظف العادي.
- ملف `schema.sql` توثيق للهجرة المطبقة خارج ملفات النشر Static، وليس جزءًا من واجهة المتصفح.

## قرارات التصميم
- **الحركة التصميمية:** تعليم هادئ بطابع editorial dashboard، يجمع الأبيض بالموف مع طبقات بنفسجية خفيفة.
- **المبادئ:** وضوح قبل الزخرفة، تقدم مرئي، بطاقات قصيرة قابلة للمسح، وواجهة RTL عملية للموبايل.
- **الألوان:** الأبيض للتركيز، الموف للهوية والأفعال، واللافندر لتمييز الحالة دون إجهاد بصري.
- **التخطيط:** عمود قراءة رئيسي مع شريط تقدم جانبي/علوي، وليس شبكة مركزية جامدة.
- **العناصر المميزة:** شارة WE دائرية، خط تقدم بنفسجي، وبطاقات وحدات ذات مؤشر حالة.
- **التفاعل:** النقر يكشف الخطوة التالية، والإجابة تكشف الشرح فورًا، مع حفظ صامت بعد كل نتيجة.
- **الحركة:** انتقالات قصيرة 180–260ms، ظهور خفيف للبطاقات، ولا توجد حركة تعيق القراءة.
- **الخط:** Cairo للعربية، بعناوين 800 ونص 400–600 وتسلسل واضح.
- **جوهر العلامة:** مدرب عملي يختصر معرفة WE لموظف جديد ويحوّلها إلى خطوة بيع/خدمة قابلة للتطبيق. الصفات: واضح، مساعد، عملي.
- **الصوت:** مباشر ومطمئن؛ أمثلة: «ابدأ من الخطوة التي تحتاجها الآن» و«الإجابة الغلط فرصة تراجع، مش نهاية الاختبار».
- **الشعار/العلامة:** استخدام شعار WE-Core الحالي داخل شارة صغيرة بجوار اسم المدرب.
- **اللون المميز:** `#6d28d9` موف WE Trainer.

## التنفيذ والملفات
- `public/index.html`: واجهة العرض الوحيدة المنشورة.
- `public/styles.css`: الهوية البصرية والاستجابة.
- `public/app.js`: تحميل البيانات، جلسة Supabase، الاختبارات، الحفظ، وتكامل `trainer-ai`.
- `public/assets/we-core.png`: شعار WE-Core.
- `public/manus-routes.json`: تعريف المسارات Static.
- `app.config.ts`: تعريف شعار مشروع Webdev، وليس ملفًا يتم تشغيله في المتصفح.
- `schema.sql`: نسخة مرجعية من الهجرة المطبقة في Supabase.
- جداول Supabase: `training_modules`, `training_videos`, `training_questions`, `training_progress` مع RLS، ودالة `get_training_team_progress` لمدير الفرع.

## حدود البيانات
لا يتم وضع أي مفتاح خدمة أو مفتاح Gemini في الواجهة. الواجهة تستخدم مفتاح Supabase العام الحالي، وتستدعي `trainer-ai` عبر JWT الموظف. مدير الفرع لا يحصل على بيانات خارج فرعه لأن القراءة تتم عبر RLS ودالة SQL مقيدة بالفرع.
